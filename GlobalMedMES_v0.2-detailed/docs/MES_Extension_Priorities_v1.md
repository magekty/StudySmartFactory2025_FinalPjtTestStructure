# MES 확장 우선순위(ERP 제외, Labor/CMMS 포함) v1.0
작성일: 2025-08-26  
전제: 40일, 4인, 현재 코어(MES: 지시→전이→실적, 권한·시간·멱등·기준선·스모크) 잠금 완료

본 문서는 “MES만 확장”한다는 가정에서, 포트폴리오 임팩트와 실무성을 동시에 높이는 5대 기능을 우선순위로 정리한다. 인원관리(노무)와 장비 유지보수(CMMS)는 반드시 포함한다.

---
## 0) 실적 -> KPI연동 반영 

- 범위(MVP)
    - 실적 수집: 생산량, 불량 수량, 공정 시간, 시작/종료 시간 등 생산 활동 데이터 수집
    - KPI 정의: 생산성, 수율, OEE(설비종합효율), 가동률 등 핵심성과지표 계산 공식 정의
    - 자동 연동: 수집된 실적 데이터를 기반으로 KPI를 실시간 또는 주기적으로 자동 계산 및 업데이트
    - 지표 시각화: 계산된 KPI를 대시보드나 리포트 형태로 시각화하여 제공

- 스키마(개략)
    - production_log: 생산 실적 데이터 (생산량, 불량량 등)
    - kpi_definition: KPI 계산 공식 정의 (매개 변수, 수식 등)
    - kpi_data: 주기적으로 계산된 KPI 결과 저장

- DoD
    - 실적 데이터 입력 시 KPI 카드 자동 업데이트
    - 생산성, 수율, OEE 등 주요 KPI를 보여주는 대시보드 뷰
    - KPI 값에 대한 기간별 추이 그래프

- 리스크/대응
    - 데이터 부정확성: 실적 수집 단계에서 데이터 검증 로직 강화
    - 복잡한 KPI 계산: 초기에는 단순한 KPI부터 시작하고, 점진적으로 고도화
    - KPI 데이터 양 증가: 데이터 아카이빙 전략 및 성능 최적화

## 1) 장비 유지보수(CMMS 라이트) — P1

- 범위(MVP)
  - PM 계획: 장비별 주기(시간/캘린더), 도래 목록
  - 보전 WO: 생성→할당→수리→종결, 비용/소요시간(라이트)
  - 고장 접수: 설비/원인 분류(손실 트리 상위 3~5개), 증상/조치 로그
  - 지표: MTBF/MTTR, PM 준수율
- 스키마(개략)
  - cmms_pm_plan, cmms_wo(header/log), cmms_fault_log, loss_category
- DoD
  - PM 계획 뷰, 보전 WO 라이프사이클, MTBF/MTTR 카드, 권한 가드
- 리스크/대응
  - 카테고리 과다 → 5개 내로 라이트 시작

---

## 2) 인원관리(노무/자격 라이트) — P1

- 범위(MVP)
  - 교대/근무 캘린더(라인/작업자), 출근기록(간이)
  - 자격/스킬 매트릭스(설비·공정별 필요자격 매핑)
  - 전이 가드: R 전이 시 “해당 설비·공정 필요자격 보유자 포함 여부” 검증
- 스키마(개략)
  - hr_shift_calendar, hr_attendance, hr_skill_matrix, hr_cert
- DoD
  - R 전이 PASS/FAIL, 교대 캘린더/출근 기록, 감사로그
- 리스크/대응
  - 개인정보/민감도 → 최소 정보·권한 분리로 시작

---

## 3) EWI/문서/전자서명 라이트 — P2

- 범위(MVP)
  - 작업지침(EWI) 업로드/버전/배포, 지시 상세에서 최신 버전 뷰
  - 전이/검사/완료 시 서명(1단계, 패스워드 확인), 감사로그
- 스키마(개략)
  - ewi_doc(header/versions), e_sign_log, audit_trail
- DoD
  - EWI 뷰·버전, 서명 입력·로그, 권한 가드
- 리스크/대응
  - 정식 Part 11은 이후 → 라이트 서명·로그로 포트폴리오 단계 완성

---

## 4) 추적/계보 라이트 + Actual 소모 — P2

- 범위(MVP)
  - Backflush 자동(표준 소모), Actual 입력/교정(대상 공정 한정), LOT 트리 뷰(간단)
- 스키마(개략)
  - wo_backflush, wo_consumption_actual, wo_material_issue(LOT)
- DoD
  - Backflush 생성, Actual 수정·저장, LOT 체인 1화면
- 리스크/대응
  - UoM/정밀도/반올림 → UoM 매핑·스케일 규칙 먼저 문서화

---

## 5) OEE/정지 분석 + 개선 액션 — P3

- 범위(MVP)
  - OEE(가용·성능·품질) 계산 라이트, 다운 원인 파레토, 개선 액션(담당/기한/상태)
- 스키마(개략)
  - oee_snapshot(view), improvement_action, downtime_cause
- DoD
  - 일/주 OEE 카드, Top 다운 원인, 액션 등록/칸반
- 리스크/대응
  - 지표 정의 혼선 → 라이트 정의(일일 기준)부터 고정

---

## 공통 설계 가드(확장에도 계속 유지)

- 시간: API=UTC ISO, 화면=KST, 비교=UTC ms
- 권한: HTTP 규칙 + @PreAuthorize + 라우트/버튼 3중
- 멱등: 생성류(이벤트/등록/서명/보전WO)는 idempotencyKey 고려
- 성능: 기간/페이지 상한, 시간·설비 인덱스, 레이트 리밋
- 감사: 주요 상태 변화(전이/서명/보전/소모) audit 로그 기록

## 40일 운영 플랜(권장)

- 주1: P1-1 CMMS 라이트(기본 테이블/화면/지표) 시작 + P1-2 인원 자격/교대 스키마·가드
- 주2: P1 마무리(보전 WO/PM/자격 연동) + P3 OEE 뼈대(다운 파레토)
- 주3: P2-1 EWI/서명 라이트 완성
- 주4: P2-2 추적/계보 라이트 + Actual 소모(대상 공정 1~2개) + 전체 폴리싱/데모

---

## 데모 스토리(권장 시나리오)

1) 교대·자격 등록 → R 전이 시 자격 PASS  
2) EWI 열람 → 작업 시작 서명  
3) 설비 다운 → CMMS 고장 접수/WO 처리 → MTTR 카드 변화  
4) 실적 등록 → Backflush 생성 → Actual로 일부 교정 → LOT 트리 확인  
5) 대시보드: OEE 카드/다운 파레토/개선 액션 진행 상황

---

## 리스크 레지스터(발생 가능성 높은 것만)

- CMMS 범위 과다 → PM/고장/보전WO 3축만 MVP
- 자격체크 복잡 → R 전이 시 “필수자격 1개 이상” 라이트 룰부터
- 문서/서명 규정 과도 → 1단계 서명+감사로그로 시작
- 계보/실소모 난이도 → 공정 1~2개, 항목 축소로 파일럿
- 지표/정의 혼선 → 라이트 정의(산식/기간) 문서로 고정
