1. 프로젝트 개요 및 목표
프로젝트 목표: 핵심 기능(BOM, 생산계획, 원가 계산)을 포함하는 ERP 시스템의 MVP(Minimum Viable Product) 백엔드를 구축하는 것입니다.

주요 기능: BOM, 생산계획, 원가 계산 모듈을 중심으로 개발을 진행했습니다.

기술 스택: 안정성과 확장성을 고려하여 Spring Boot 3.5.4와 Java 17을 기반으로 설계되었으며, 데이터베이스는 MySQL 8을 사용합니다.

개발 기간: 2025년 9월 15일부로 1차 개발을 완료했습니다.

2. 핵심 기능 구현 상세
1) BOM (자재명세서) 관리
BOM 헤더/라인 관리: 제품 생산에 필요한 원자재 및 부품 정보를 계층적으로 관리합니다.

성능 최적화: BOM 라인 조회 시, 불필요한 쿼리 호출을 막기 위해 **Fetch Join**을 적용하여 N+1 문제를 해결했습니다.

데이터 유효성: DB 스키마에 UUID를 PK로 사용하고, BOM 고유성을 보장하기 위한 유니크 제약조건을 설정했습니다.

2) 생산계획 관리
계획 수립: 생산계획 생성 시, 관련된 BOM의 유효성을 검증하여 정확한 계획 수립을 돕습니다.

상태 관리: 생산계획의 진행 상태를 체계적으로 관리하기 위한 상태 전이(State Transition) API를 구현했습니다. 상태는 DRAFT, CONFIRMED, IN_PRODUCTION, COMPLETED, CANCELED로 구분됩니다.

유연성: 상태 전이 API를 통해 생산 계획의 라이프사이클을 명확하게 추적하고 관리할 수 있습니다.

3) 원가 계산 프로세스
기준 계산 방식: 
+직접 재료비(MaterialCost-std_cost*qty)
+직접 노무비(직접 재료비*수동 비율)
+제조 간접비(직접 재료비*수동 비율)
or
+직접 재료비(MaterialCost-std_cost*qty)
+추후 공정별 소요시간*공정 단가(실제 인건비)
+제조 간접비(직접 재료비*수동 비율)

계산 방식: 두 가지 기준에 따라 원가를 계산합니다.

제품 기준(by-product): 특정 제품과 수량을 입력하여 원가를 계산합니다.

생산계획 기준(by-plan): 특정 생산계획을 기준으로 원가를 계산합니다.

데이터 처리:

미리보기: GET API를 통해 계산 결과만 반환하며, DB에 저장하지 않아 실시간 시뮬레이션이 가능합니다.

결과 저장: POST API를 통해 계산된 원가 결과를 cost_snapshot 및 cost_snapshot_detail 테이블에 저장하여 이력을 관리합니다.

3. 아키텍처 및 기술 정책
1) 안정성 및 확장성
DTO 응답 원칙: 엔티티 객체를 직접 노출하지 않고 DTO(Data Transfer Object)로 변환하여 응답합니다. 이는 데이터 노출을 최소화하고 직렬화 충돌을 방지합니다.

논리 삭제(is_deleted): 데이터를 물리적으로 삭제하지 않고 is_deleted 컬럼 값을 변경하여 관리합니다. 이는 데이터 복구 용이성을 높입니다.

낙관적 락(version): version 컬럼을 사용하여 동시성 제어를 구현했습니다. 여러 사용자가 동시에 데이터를 수정할 때 데이터 충돌을 방지하여 데이터 무결성을 보장합니다.

UUID PK: 분산 환경에서도 충돌 없이 고유한 값을 가지는 **UUID(CHAR(36))**를 PK로 사용하여 향후 시스템 확장에 유연하게 대비했습니다.

2) 데이터 정밀도
통화: 한국 원화(KRW)를 사용하며, 최종 표시는 소수점 2자리까지 권장합니다.

수량/내부 계산: 정밀한 계산을 위해 내부적으로 소수점 6자리까지 유지합니다.

4. 배포 및 향후 계획
1) 배포 준비 현황
환경 설정: application.yml 파일 내 데이터베이스 접속 정보와 서버 포트(8081)를 확인했습니다.

API 문서: **Swagger UI(/swagger-ui)**를 통해 모든 API 명세를 제공하여 개발자 간의 협업을 용이하게 합니다.

통합 테스트: .http 스크립트를 사용하여 핵심 시나리오(제품 생성 → BOM/생산계획 → 원가 계산)에 대한 통합 테스트를 완료했습니다.

2) 다음 단계
Flyway 도입: 스키마 버전 관리를 자동화하여 DB 변경 이력을 체계적으로 관리할 예정입니다.

입력 유효성 검증 강화: 사용자 입력값에 대한 상세한 Validation 메시지를 추가하여 유효하지 않은 데이터가 시스템에 유입되는 것을 방지합니다.

로깅: 로그 레벨을 정리하고 민감 정보(예: 비밀번호, 개인정보)를 마스킹하여 보안을 강화할 계획입니다.
