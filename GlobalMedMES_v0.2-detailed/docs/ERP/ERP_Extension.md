# 생산계획 ERP FE 확장 명세 (P/R/C + 워크플로 배지) — Draft v1.0

본 문서는 기존 ERP C# WPF 생산계획 화면(목록/신규/수정·소프트삭제: 기간·품목·삭제포함 검색, 컬럼: planId, lineNo, item, qty, uom, due, priority, deleted, updatedAt)을 기반으로, 합의된 범위를 확장하기 위한 기획·설계 명세다. ERP DB 도입 전/후 모두 FE 변경 최소화를 목표로 한다.

---

## 1) 목적/범위

- 목적: 생산계획 목록에서 “현재 실행 상태”를 직관적으로(P/R/C) 확인하고, 상세에서 BOM·재고·부족을 정확히 판단하도록 정보 구조를 보강.
- 범위:
  - 목록: P/R/C 메인 상태 + 워크플로 보조배지(생성/승인/배포/보류/취소), 상태 필터.
  - 상세: BOM 미리보기, 재고 스냅샷, 부족 리스트.
  - 데이터 소스: ERP DB 도입 전에는 MES로부터 상태/재고/검증 정보를 보조 조회(읽기 전용). ERP DB 도입 후 동일 계약으로 소스 전환.

---

## 2) 합의 사항 요약

- 메인 상태는 P/R/C 3단계, 근거는 “MES WO 상태 집계”.
- 목록에서는 HasShortage 컬럼 미사용. 부족 여부는 상세에서만 계산/표시.
- 워크플로 상태(생성/승인/배포/보류/취소)는 보조 배지로만 노출.
- ERP DB 도입 전까지, 계획 조회는 기존 ERP FE 저장소를 사용하되, 상태·재고 등은 MES 보조 의존.
- BOM 직조회 기본값: rev=A, alt=STD.

---

## 3) 상태 모델 정의

### 3.1 메인 상태(P/R/C) 파생 규칙
- C(Completed): 연결된 WO가 있고, “모든 WO가 완료/종료”.
- R(Running/Released): 연결된 WO 중 “하나라도 진행/배포/실행 중”.
- P(Planned): 그 외 전부(연결된 WO 없음 포함).

우선순위: “모두 완료” → C, 그 외에 “하나라도 진행” → R, 그 외 → P.

WO 원천 상태의 정규화(예시)
| 원천 WO 상태 | 정규화 그룹 |
|---|---|
| EXECUTING, RUNNING, RELEASED | R |
| COMPLETED, CLOSED | C |
| CREATED, APPROVED, SCHEDULED, NONE | P |

주의: 메인 상태는 항상 WO 상태만으로 판정(워크플로 보조배지와 분리).

### 3.2 워크플로 보조배지
- 생성, 승인, 배포, 보류, 취소를 칩 형태로 표시(한글 표기).
- 취소: 행을 연회색 처리(읽기 전용 느낌). 메인 상태는 P/R/C 규칙대로 유지.
- 보류: 노란 배지, 툴팁에 사유 노출(있을 경우).

## 4) 화면 사양

### 4.1 목록(List)
- 기존 컬럼 유지: planId, lineNo, item, qty, uom, due, priority, deleted, updatedAt
- 추가 컬럼/표기:
  - status(P/R/C): 메인 상태
  - source(ERP|MES): 데이터 출처(선택)
  - bomRev, bomAlt: 짧은 텍스트(선택)
  - 보조배지: [생성][승인][배포][보류][취소]
- 필터:
  - 기간(필수), 품목, 삭제포함 토글(기존), status(P/R/C)
- 정렬:
  - 기본: due 오름차순
  - 보조: priority, updatedAt
- 시각 규칙:
  - Past Due: 빨강 점
  - Due Soon(48시간 이내): 주황 점
  - 취소: 행 텍스트 연회색 + [취소] 배지

성능 가이드:
- 서버 페이징(페이지당 50~100), 가상화.
- 상태 계산은 “현재 페이지의 planId 묶음”에 대해 MES 배치 조회 1회.
- 상태 캐시 TTL 30~60초(페이지 전환 시 재사용).

### 4.2 상세(Detail)
- 헤더 카드:
  - planId, item, qty/uom, due, priority, updatedAt
  - status(P/R/C), 워크플로 타임라인(생성→승인→배포→보류/취소/완료)
- BOM 미리보기:
  - 라인No, component, qty, uom, scrap%, 상태(Unknown/Deleted 배지)
- 재고 스냅샷:
  - 온핸드, 할당, 입고예정, 가용(기본 단위)
- 부족 리스트:
  - component, reqQty, avail, shortage(음수), substitute 힌트(있을 때)
  - 소요량(스크랩 반영) 계산식:
    - $$ Q_{\text{req}} = \frac{Q_{\text{per}} \times Q_{\text{plan}}}{1 - s} $$
- 선택(옵션): Ready% 바
  - $$ Ready = \min_i \left( \frac{\text{가용재고}_i}{\text{소요량}_i} \right) $$

## 5) 데이터 소스·계약(개념)

- 목록(ERP FE 저장소): 기존 조회/신규/수정·소프트삭제 흐름 유지.
- 상태 배치 조회(MES 보조): planId 다건 입력 → 각 planId의 WO 상태 리스트 반환.
  - 파생 로직: 메인 상태는 3.1 규칙으로 FE에서 도출.
- BOM 직조회(MES): itemId 기준, rev/alt(기본 A/STD).
- 재고 가용(MES): itemId 기준 시점별 온핸드/할당/입고예정/가용.

전환 전략:
- ERP DB 도입 후에도 위 계약을 유지하고, 데이터 소스만 ERP로 스위칭(어댑터로 정규화).

## 6) 성능·캐시·재시도 정책

- 목록 SLA: 1천 건 조회 < 1.5초, 상세 API < 500ms 목표.
- 네트워크:
  - 타임아웃 3~5초, 재시도 1~2회(멱등 GET에 한함), 취소 토큰(페이지 전환 시 이전 요청 취소).
- 캐시:
  - 상태 배치 결과 TTL 30~60초(페이지 단위), 재고·BOM은 상세 진입 시 즉시 조회.
- 스케줄/쿨다운(참고):
  - DEV: 30초 권장, 운영: 5분 이상 가능(동기화/리트라이 기준).

---

## 7) 오류/예외 UX

- 공통: 토스트 + “상세 보기”에 상관관계 ID 노출.
- 부분 실패: 목록 셀에 에러 아이콘(툴팁에 메시지).
- 데이터 불일치:
  - BOM Unknown/Deleted: 상세에서 경고 배지, 목록에는 아이콘(선택).
  - 상태 불명확(배치 응답 누락): status를 P로 표시 + 옅은 회색 점 + “상태 확인 필요” 툴팁.
